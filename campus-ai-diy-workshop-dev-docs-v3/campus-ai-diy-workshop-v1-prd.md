# 校园轻活动 AI DIY 工坊 V1.0 需求文档（简版）

**文档版本：** V1.0  
**产品形态：** 移动端 Web/H5 活动页面制作与发布工具  
**更新日期：** 2026-10-26

## 1. 产品概述

### 1.1 产品定位

面向学生社团、班团组织和活动负责人，提供 AI 辅助的移动端 Web 活动页面制作工具。

用户可以通过模板、一句话描述或上传活动海报创建页面，再通过可视化编辑完成设计，最终发布链接、二维码和分享海报，并收集报名、投票或打卡数据。

### 1.2 产品口号

> 上传一张活动海报，快速生成能报名、能分享、能统计的活动页面。

### 1.3 交付边界

第一版交付物为移动端 Web/H5，可直接通过手机浏览器访问，不依赖微信小程序运行时。

本产品中的“小程序式组件”指具有小程序交互特征的移动端 Web UI 组件，不等同于微信原生小程序组件。

### 1.4 双端交付方式

V1 使用一套 Next.js 前端工程，通过不同路由和页面外壳提供两种体验：

- 电脑端 Web：组织者工作台，支持项目管理、完整 DIY 编辑、AI 建议、发布和查看数据。
- 移动端 Web：参与者活动页，支持活动浏览、报名、投票、打卡和表单提交，无需登录。

两端共用 PageDocument、组件渲染器和 API 客户端。第一版不把完整拖拽编辑器搬到手机端；手机端仅提供项目查看、分享和基础数据查看等组织者能力。

## 2. 目标用户

### 2.1 主要用户

社团负责人、班委和活动组织者。

典型需求包括：

- 制作活动报名页
- 收集成员信息
- 发起投票或评选
- 组织每日打卡
- 分享活动并查看报名情况

### 2.2 次要用户

参与活动的学生。

参与者通过链接或二维码进入手机端 Web 页面，可以查看活动信息并提交表单，无需安装应用。

## 3. 核心流程

> 创建项目 → 上传海报或输入需求 → AI 生成活动页面 → 可视化编辑 → AI 优化建议 → 手机预览 → 发布分享 → 收集数据

## 4. V1 功能范围

| 模块 | P0 第一版需求 |
|---|---|
| 项目管理 | 新建、编辑、复制、删除活动项目；查看发布状态 |
| 模板中心 | 社团招新、活动报名、投票评选、每日打卡 |
| AI 创建 | 根据一句需求生成活动页面初稿 |
| 海报解析 | 从活动海报中提取名称、时间、地点、报名信息并支持人工修改 |
| 多页面管理 | 支持首页、介绍页、表单页、成功页等页面创建和跳转 |
| 组件库 | 导航栏、Banner、标题、文本、图片、信息卡片、按钮、表单、单选框、多选框、二维码 |
| 可视化编辑 | 添加、删除、复制、拖拽排序及属性修改 |
| 样式编辑 | 修改主题色、字号、间距、圆角、背景和按钮样式 |
| AI 辅助 | 根据选中组件和当前页面提供文案、配色、布局建议 |
| AI 质量检查 | 检查表单缺失、文案过长、对比度不足、移动端溢出等问题 |
| 预览与发布 | 手机尺寸预览、发布链接、二维码和简单分享海报 |
| 表单提交 | 必填校验、报名截止时间、人数上限、成功提示 |
| 数据管理 | 查看报名、投票和打卡记录，支持 CSV 导出 |
| 版本能力 | 自动保存、撤销、重做和恢复历史版本 |

## 5. 产品页面与流程

### 5.1 项目工作台

组织者登录后可以：

- 查看最近编辑的项目
- 新建活动
- 从模板创建
- 上传海报创建
- 查看已发布活动及数据

### 5.2 创建页面

支持两种创建方式：

1. **模板创建：** 从社团招新、活动报名、投票评选或每日打卡模板开始。
2. **AI 创建：** 输入活动需求，或上传海报自动提取信息。

### 5.3 DIY 编辑器

编辑器采用四区域布局：

- 左侧：页面列表、模板和组件库
- 中间：手机尺寸画布
- 右侧：组件属性、样式配置和 AI 建议
- 顶部：撤销、重做、预览、发布

第一版采用单列移动端画布、网格拖拽排序和受控组件，不实现任意绝对定位和自由画布。

### 5.4 参与者页面

参与者可以通过链接或二维码访问活动页面，完成报名、投票、打卡或问卷提交，并查看提交成功页。

### 5.5 数据后台

组织者可以查看提交数量、选项分布和提交记录，并导出 CSV 文件。

## 6. AI 能力要求

AI 包含三项核心能力：

1. **页面生成：** 将自然语言或海报信息转换为结构化页面。
2. **编辑 Copilot：** 根据当前选中的组件、页面内容和相邻组件给出可执行建议。
3. **发布前检查：** 检查信息层级、表单完整性、按钮文案、对比度和移动端适配。

AI 不直接生成可执行的 HTML、CSS 或 JavaScript，而是输出受控的页面结构和修改指令，例如：

- 插入组件
- 修改组件属性
- 更换主题
- 调整组件顺序
- 替换文案
- 设置页面跳转

所有修改需要：

- 展示修改原因
- 提供修改前后对比
- 由用户确认后应用
- 支持撤销和恢复

## 7. 示例场景

以“摄影社招新”为例，上传招新海报后，系统自动生成：

> 首页 → 社团介绍 → 部门介绍 → 报名表单 → 报名成功页

用户可以进一步：

- 将主按钮文案改为“立即报名”
- 增加联系方式字段
- 调整更符合摄影社风格的配色
- 插入活动照片
- 设置报名截止时间
- 发布活动并生成二维码
- 查看报名人数和部门选择分布

## 8. 数据模型

第一版需要保存以下数据：

- 用户
- 活动项目
- 页面结构
- 页面版本
- 发布配置
- 表单定义
- 用户提交记录
- AI 修改记录

活动链接发布后，应支持更新页面内容而保留原访问地址。

## 9. 非功能要求

- 移动端优先，重点适配 375px～430px 手机屏幕。
- 支持桌面端预览和基础管理功能。
- 活动用户无需安装额外工具，可直接通过浏览器访问。
- 编辑内容定期自动保存，异常退出后可恢复。
- 上传文件限制格式和大小，防止恶意文件。
- 用户输入和 AI 生成内容需要经过校验，禁止注入脚本。
- 活动组织者的数据与参与者提交记录需要隔离。
- AI 服务异常时保留手动编辑和模板创建能力。

## 10. V1 验收标准

第一版至少通过以下测试：

1. 输入一句招新需求，能够生成包含介绍、部门和报名表单的页面。
2. 上传活动海报，能够提取主要活动信息并允许用户修改。
3. 可以添加组件、修改文案、拖拽排序并撤销操作。
4. 选中组件后，AI 能结合页面上下文给出至少一条可执行建议。
5. 系统能够检查出未填写的关键表单字段或按钮文案问题。
6. 页面可以发布为手机端 Web 链接并生成二维码。
7. 参与者能够提交报名信息，组织者能够在后台查看并导出数据。
8. 同一份活动页面可以更新内容，且原链接继续有效。
9. 简单分享海报可以包含活动名称、时间、地点和报名二维码。

## 11. V1 暂不包含

- 真正的微信原生小程序创建和提交审核
- 微信小程序代码导出
- 任意自由拖拽和复杂动画编辑
- AI 图片生成和视频生成
- 在线支付、抽奖和营销组件
- 多人实时协作
- 复杂用户权限体系
- 自定义域名
- 线上部署和服务器购买功能

## 12. 版本目标

V1 的重点是完成以下完整闭环：

> 海报或需求输入 → AI 建页 → DIY 修改 → 发布分享 → 数据收集

第一版不建设覆盖所有场景的通用低代码平台，而是聚焦校园轻量活动场景，优先保证核心流程稳定、可演示和可实际使用。
