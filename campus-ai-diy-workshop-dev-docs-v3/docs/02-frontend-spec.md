# 前端产品与技术规格

## 1. 前端目标

前端提供两个明显不同的使用场景：

1. **组织者工作台：** 创建、生成、编辑、预览、发布和查看数据。
2. **参与者活动页：** 手机优先、无需登录、快速完成报名或投票。

公共活动页与编辑器应共享同一套 PageDocument 渲染组件，避免“编辑时看起来正确，发布后布局不同”。

## 2. 路由设计

| 路由 | 页面 | 是否需要登录 |
|---|---|---|
| `/login` | 登录与注册 | 否 |
| `/projects` | 项目工作台 | 是 |
| `/projects/new` | 创建项目与选择模板 | 是 |
| `/editor/[projectId]` | DIY 编辑器 | 是 |
| `/projects/[projectId]/submissions` | 提交数据 | 是 |
| `/templates` | 官方模板中心 | 是 |
| `/p/[slug]` | 公共活动首页 | 否 |
| `/p/[slug]/[pagePath]` | 公共活动子页面 | 否 |
| `/p/[slug]/success` | 提交成功页 | 否 |

公共页面通过 Web 路由进入，不依赖微信开发者工具。

## 3. 页面结构

### 3.1 项目工作台

展示：

- 项目标题、封面、活动状态
- 最后编辑时间
- 发布状态：草稿、已发布、已下线
- 提交数量
- 新建、复制、归档操作

空状态提供“从模板创建”和“上传海报创建”。

### 3.2 创建项目页

支持：

- 输入活动名称
- 选择模板
- 输入一句需求
- 上传海报 JPG/PNG/WebP
- 点击生成后跳转编辑器并显示生成进度

海报上传后需要展示提取结果，用户可以修改活动名称、时间、地点、报名截止时间和联系方式。

### 3.3 DIY 编辑器

编辑器由五个区域组成：

```text
┌────────────────────────────────────────────────────────┐
│ 顶部：项目名 / 保存状态 / 撤销 / 重做 / 预览 / 发布       │
├──────────┬─────────────────────────────┬───────────────┤
│ 页面列表 │                             │ 属性 / 样式    │
│ 组件库   │       手机端画布             │ AI 建议        │
│ 页面大纲 │                             │               │
└──────────┴─────────────────────────────┴───────────────┘
```

#### 左侧

- 页面列表：新增、重命名、复制、删除、设为首页
- 组件库：按基础、展示、表单、互动分组
- 当前页面组件树：拖拽排序和选中

#### 中间

- 手机宽度画布，推荐 390px 作为设计基准
- 组件 hover 边框与选中状态
- 拖拽插入指示线
- 不允许自由绝对定位
- 支持缩放适配桌面屏幕

#### 右侧

- 属性面板
- 样式面板
- 页面设置
- AI 建议列表

AI 建议卡片包含：问题、原因、影响组件、修改预览、采纳、忽略和撤销。

### 3.4 预览与发布

- 手机尺寸预览
- 公开链接
- 下载二维码
- 分享海报预览与下载
- 报名截止时间、人数上限和活动状态设置
- 发布前质量检查结果

### 3.5 数据后台

- 提交总数
- 最近提交列表
- 单字段分布
- 提交详情抽屉
- 搜索和筛选
- CSV 导出
- 删除或标记无效记录前需要二次确认

### 3.6 公共活动页

- 手机优先全宽布局
- 支持活动分页和返回
- 表单前端校验
- 防重复点击
- 提交中、成功、截止、名额已满、已下线等状态
- 不使用编辑器侧栏和任何管理员入口

## 5. 编辑器状态管理

Zustand 建议拆分四个 store：

- `projectStore`：项目、发布状态、草稿 revision
- `editorStore`：PageDocument、当前页面、选中组件、undo/redo 栈
- `aiStore`：Job、建议、应用/拒绝状态
- `uiStore`：侧栏、弹窗、预览设备、保存状态

### 自动保存

1. 用户操作发生后进入 1 秒防抖队列。
2. 前端提交整份 PageDocument 和 `baseRevision`。
3. 后端 revision 不匹配时返回 `409 REVISION_CONFLICT`。
4. 冲突时不静默覆盖，向用户提供“刷新最新草稿”或“保留本地副本”。
5. 发布前强制保存并生成独立 PageVersion。

### 撤销/重做

- 只记录 PageDocument 编辑操作，不记录 AI 网络请求。
- AI Proposal 应用后作为一个完整 undo step。
- 应用建议后立即触发自动保存。

## 7. 组件渲染规则

组件注册表只渲染白名单类型：

```ts
type ComponentDefinition = {
  type: string
  displayName: string
  category: "layout" | "basic" | "form" | "interaction"
  propSchema: ZodType
  defaultProps: Record<string, unknown>
  render: React.ComponentType<{
    props: unknown
    mode: "edit" | "preview" | "public"
  }>
}
```

渲染器遇到未知组件或无效属性时：

- 编辑器显示可理解的错误占位，不崩溃。
- 发布前检查将其标记为阻断项。
- 公共页面跳过非关键未知组件，并返回监控事件。

## 8. AI 前端交互

### 一句话生成

- 用户提交后显示步骤：“理解需求 → 生成页面 → 检查结构”
- 任务超时提供重试和从模板创建入口
- 结果以完整草稿出现在编辑器中

### 组件建议

- 用户选中组件后点击“AI 优化”或输入自然语言指令
- 建议默认不自动应用
- 用户可逐条采纳或全部采纳
- 应用后显示 toast 和“撤销”

### 发布前检查

阻断问题必须处理后才能发布，例如：

- 表单没有提交按钮
- 按钮跳转到不存在的页面
- 首页缺失
- 页面标题为空

非阻断问题可带着提示发布，例如：

- 文案过长
- 图片缺少 alt
- 对比度可能不足

## 9. 电脑端与移动端实施方案

### 9.1 核心决策

V1 不开发两套独立前端，也不分别建设电脑网站和手机网站。推荐使用同一套 Next.js 工程，通过不同路由、页面外壳和代码分包服务两类用户：

- 电脑端 Web：组织者工作台，负责创建、编辑、发布和管理数据。
- 移动端 Web：参与者活动页，负责查看活动、报名、投票、打卡和提交。
- 两端共用 PageDocument、组件渲染器、表单组件、API 客户端和设计变量。

```text
一套 Next.js 前端
├── 电脑端工作台
│   ├── 项目列表
│   ├── 创建项目
│   ├── 三栏 DIY 编辑器
│   ├── 发布设置
│   └── 提交数据后台
├── 移动端公共页
│   ├── 活动首页
│   ├── 活动介绍页
│   ├── 报名/投票/打卡表单
│   └── 提交成功页
└── 共享能力
    ├── PageDocument Schema
    ├── 无状态组件渲染器
    ├── 表单校验
    ├── API Client
    └── 主题与设计变量
```

### 9.2 双端职责

| 能力 | 电脑端组织者 | 移动端参与者 |
|---|---|---|
| 查看活动 | 是 | 是 |
| 创建和编辑页面 | 完整支持 | 不支持 |
| 拖拽组件 | 支持 | 不支持 |
| 修改属性与主题 | 支持 | 不支持 |
| 查看 AI 建议 | 支持 | 不支持 |
| 手机尺寸预览 | 支持 | 不需要 |
| 发布和二维码 | 支持 | 不支持 |
| 查看提交数据 | 支持 | 不支持 |
| 填写并提交表单 | 预览模式支持 | 完整支持 |

电脑端是生产工具，移动端是消费入口。V1 不把完整编辑器搬到手机端。

### 9.3 电脑端页面框架

电脑端编辑器以 1280px 以上为主要工作宽度，最低完整支持 1024px：

```text
┌───────────────────────────────────────────────────────────┐
│ 项目名 / 保存状态 / 撤销 / 重做 / 手机预览 / 发布          │
├─────────────┬────────────────────────────┬────────────────┤
│ 页面列表    │                            │ 组件属性        │
│ 组件库      │       390～430px 画布       │ 样式设置        │
│ 页面大纲    │                            │ AI 建议         │
└─────────────┴────────────────────────────┴────────────────┘
```

实现要求：

- 使用 dnd-kit 完成组件拖拽排序。
- 使用 Zustand 管理当前页面、选中组件和 undo/redo。
- 中间画布固定为手机设计宽度，但组件必须支持流式宽度。
- 右侧属性面板根据选中的组件类型动态渲染。
- 编辑器壳层使用动态导入，避免进入公共活动页时下载拖拽和编辑代码。
- 小于 900px 时显示“建议使用电脑进行精细编辑”，但项目列表和数据查看仍可访问。

### 9.4 移动端页面框架

公共活动页以 390px 为设计基准，兼容 375～430px，桌面访问时居中显示并限制最大内容宽度：

```text
┌──────────────────────┐
│ 导航栏               │
│ 活动 Banner          │
│ 活动标题与介绍       │
│ 时间、地点、联系人   │
│ 部门或活动信息       │
│ 报名表单             │
│ 提交按钮             │
└──────────────────────┘
```

实现要求：

- 使用单列流式布局。
- 页面宽度为 100%，内容容器建议最大 640px。
- 点击区域不小于 44×44px。
- 图片和文本不得导致横向滚动。
- 表单错误提示紧跟字段。
- 提交按钮可随内容滚动，也可根据模板设为底部固定。
- 活动页不加载编辑器侧栏、拖拽库和 AI 建议组件。
- 参与者无需登录即可查看和提交公开活动。

### 9.5 共用渲染器

编辑画布、电脑预览和公共活动页必须使用同一个无状态渲染组件：

```tsx
<ActivityRenderer
  document={pageDocument}
  currentPageId={currentPageId}
  mode="edit" | "preview" | "public"
  onComponentSelect={handler}
/>
```

约束：

- 渲染器只负责根据 PageDocument 展示内容。
- 编辑器选中框、属性面板和拖拽手柄属于编辑器壳层，不能进入公共页面 bundle。
- 同一组件的 `preview` 和 `public` 渲染结果必须一致。
- 不同模式只允许附加交互处理，不允许改变组件基础布局。

### 9.6 响应式策略

电脑编辑器中间画布的屏幕宽度仍是桌面宽度，不能用 `@media (max-width)` 判断画布内部是否为手机。因此组件渲染器应遵循：

- 组件采用移动端优先的流式布局。
- 使用百分比、`minmax()`、`clamp()` 和 CSS Grid 自适应。
- 需要按可用宽度变化时使用 Container Queries，容器包含编辑器画布和公共页内容区。
- 页面级外壳可以使用媒体查询控制侧栏、顶部导航和编辑器布局。
- 公共页在桌面浏览器中保持居中，不强行改成多栏活动页。

推荐断点只用于产品外壳：

| 断点 | 用途 |
|---|---|
| `< 768px` | 移动端项目查看、公共活动页 |
| `768～1023px` | 平板项目管理和数据查看，提示精细编辑使用电脑 |
| `>= 1024px` | 完整编辑器 |
| `>= 1280px` | 优化后的三栏编辑器 |

### 9.7 路由与代码分包

```text
app/
├── (workspace)/
│   ├── projects/page.tsx
│   ├── projects/new/page.tsx
│   ├── projects/[projectId]/page.tsx
│   ├── editor/[projectId]/page.tsx
│   └── projects/[projectId]/submissions/page.tsx
├── p/[slug]/page.tsx
├── p/[slug]/[pagePath]/page.tsx
└── p/[slug]/success/page.tsx
```

分包要求：

- `(workspace)` 页面加载组织者工作台代码和编辑器依赖。
- `/p/[slug]` 只加载公共渲染器、表单和必要的 API 客户端。
- dnd-kit、属性面板、AI 侧栏通过编辑器路由或动态导入加载。
- 公共页不能依赖组织者登录状态。

### 9.8 电脑端与移动端认证

- 组织者访问 `(workspace)` 时使用登录会话。
- 公共页 `/p/[slug]` 使用发布快照，不要求登录。
- 表单提交接口使用公开限流、字段白名单和幂等键。
- 手机端不需要访问草稿、项目设置或 AI 接口。

### 9.9 V1 手机端组织者能力

为控制工作量，组织者手机端只提供：

- 查看项目列表
- 查看活动发布状态
- 复制分享链接
- 打开二维码
- 查看提交列表和总数
- 暂停或重新开放活动

页面编辑、组件拖拽和 AI 优化仍放在电脑端。

### 9.10 推荐开发顺序

1. 定义 PageDocument 和组件属性 Schema。
2. 实现无状态 ActivityRenderer。
3. 先完成 `text`、`button`、`form` 三个组件的公共移动页。
4. 完成项目列表和创建项目。
5. 完成电脑端三栏编辑器与自动保存。
6. 接入发布快照、公共活动页和表单提交。
7. 接入 AI Job、建议与质量检查。
8. 使用桌面 1440px 和手机 390px 两个视口做 Playwright 回归。

### 9.11 双端验收

- 电脑端能从模板创建、编辑、预览和发布活动。
- 页面在编辑器画布和公共手机页中布局一致。
- 手机扫码后可提交报名，不要求登录。
- 公共活动页不下载编辑器相关代码。
- 电脑端修改草稿不会改变已发布手机页面。
- 在 375px、390px、430px 手机宽度下无横向滚动。
- 在 1024px、1440px 桌面宽度下编辑器完整可用。

## 10. 移动端与可访问性

- 设计基准 390×844，兼容 375～430px。
- 点击区域最小 44×44px。
- 按钮和正文满足基础颜色对比度。
- 表单字段必须有 label。
- 图片组件提供 alt，装饰图片允许显式设置为空。
- 公共页不依赖 hover。
- 抽屉和弹窗具备键盘关闭与焦点管理。

## 11. 前端验收清单

- 新建项目后可以进入编辑器。
- 页面渲染器在编辑、预览、发布三种模式下结果一致。
- 拖拽排序和属性修改可撤销。
- AI 建议未确认前不改变页面。
- 发布新版本不影响正在访问的旧版本快照。
- 手机端可正常填写和提交表单。
- 409 草稿冲突可见且不会丢数据。
- 未知组件不会导致整个活动页白屏。
