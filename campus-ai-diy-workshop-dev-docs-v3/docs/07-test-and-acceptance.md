# 测试、联调与验收

## 1. 测试分层

| 层级 | 范围 | 工具 |
|---|---|---|
| 单元测试 | Schema、工具操作、权限、校验 | Vitest / pytest |
| 组件测试 | 编辑器、渲染器、表单 | React Testing Library |
| API 集成测试 | 项目、版本、发布、提交 | pytest + 测试数据库 |
| E2E | 从创建到提交的完整流程 | Playwright |
| 安全测试 | 越权、上传、限流、注入 | 自动化 + 人工测试 |
| 可用性测试 | 社团组织者完成建页 | 真实用户试用 |

## 2. 统一测试数据

固定一套招新测试数据：

```text
项目：摄影社 2026 秋季招新
页面：首页、社团介绍、部门介绍、报名表、报名成功
```

每次代码变更后，至少运行创建、编辑、发布、提交这一主流程。

## 3. P0 验收用例

### A. 项目与模板

- 注册并登录后进入项目工作台。
- 从四个模板任一创建项目。
- 复制项目不共享草稿和提交数据。
- 其他用户不能访问该项目。

### B. 编辑器

- 添加、删除、复制和拖拽组件。
- 修改标题、文案、图片、颜色和跳转。
- 撤销和重做行为正确。
- 自动保存后刷新页面不丢内容。
- 旧 revision 保存返回 409，不静默覆盖。

### C. 页面结构

- 首页 ID 必须存在。
- 按钮不能跳转到不存在的页面。
- 不支持组件类型不会导致页面白屏。
- 发布前阻断问题能够被检测。

### D. 海报解析

- 上传合法 JPG/PNG/WebP 后得到可编辑活动信息。
- 低置信度字段明确标记，未识别字段保持为空。
- 恶意图文中的指令不会改变系统规则。
- 大文件、伪造扩展名和不支持格式被拒绝。

### E. AI 建议

- 选中按钮后能获得针对该组件的文案或样式建议。
- 建议包含原因和修改预览。
- 未确认前草稿不变化。
- 确认后 revision 增加，撤销后恢复。
- 基于旧 revision 的建议被标记为 stale。

### F. 发布

- 发布后获得公开链接和二维码。
- 公共页只展示发布版本。
- 继续编辑草稿不改变线上内容。
- 再次发布后线上切换为新版本。
- 下线后公共页显示已停止访问。

### G. 表单提交

- 必填项、选项、长度和 URL 校验正确。
- 截止时间和人数上限生效。
- 重复点击不会生成重复提交。
- 参与者无法提交未定义的字段。
- 不同活动之间提交数据隔离。

### H. 数据后台

- 列表分页和搜索正确。
- CSV 导出字段、中文编码和权限正确。
- 无效记录可标记，但不暴露敏感数据。

## 4. API 契约测试

CI 中应从 OpenAPI 生成客户端并进行契约检查：

- 请求字段名和必填规则一致。
- 错误响应统一。
- 401、403、404、409、422、429 可区分。
- 分页结构一致。
- 时间使用 ISO 8601 UTC。
- 公开接口不返回内部敏感字段。

推荐工具：

- Schemathesis：基于 OpenAPI 的 API 属性测试。
- `openapi-typescript`：生成前端类型。
- `openapi-fetch` 或 Orval：生成 API 客户端。

## 5. 安全验收

- 用户 A 使用用户 B 的 projectId 获取草稿返回 404 或 403。
- 公共活动接口不能读取 draft。
- 提交接口不能写其他活动。
- 导出文件链接不能长期公开访问。
- 图片 SVG 或脚本内容不会被直接渲染；如需 SVG 应清洗或转成安全格式。
- PageDocument 中的 HTML 被严格限制或完全禁止。
- AI 提案不能包含未知工具。
- AI 提案不能修改 ownerId、projectId、revision 等系统字段。
- 登录、AI、上传和提交接口有限流。
- 日志不出现密码、JWT、完整表单数据或模型密钥。

## 6. 浏览器与设备

至少测试：

- Chrome 最新版
- Edge 最新版
- Safari iOS 最新两个大版本
- Android Chrome 最新版
- 375px、390px、430px 三种手机宽度
- 1366px 桌面编辑器

公共活动页以真实手机浏览器测试，不以桌面开发者工具为唯一依据。

## 7. 性能目标

目标值用于 V1 联调，不作为绝对硬指标：

- 公共活动页首屏可交互时间在普通校园网络下尽量小于 3 秒。
- 公共页不加载编辑器依赖。
- 单次草稿自动保存接口 P95 小于 800ms，不含网络异常。
- 常规页面访问不调用 AI。
- AI 请求异步执行，前端展示进度，不阻塞编辑器打开。
- 图片提供缩略图，避免首屏加载原图。

## 8. 可访问性与体验

- 所有表单字段有可识别标签。
- 错误提示紧邻对应字段。
- 键盘可完成桌面端编辑基础操作。
- 弹窗支持 Esc 关闭和焦点恢复。
- 按钮点击区不小于 44×44px。
- 状态变化不能只依靠颜色。
- 公共页文字可缩放，不出现固定宽度溢出。

## 9. 真实用户试点

至少邀请 2 个学生组织完成以下测试：

1. 上传真实海报。
2. 选择模板或使用 AI 生成。
3. 在 10 分钟内完成编辑器修改。
4. 发布活动并发送给同学。
5. 收集至少 10 份真实提交。
6. 查看数据和导出。

记录：

- 建页总时长
- 卡住的步骤
- AI 建议是否被采纳
- 手动返工次数
- 参与者提交成功率
- 最需要的缺失功能

这些记录可以作为答辩中的真实证据。
